# Journal des versions

## 1.1.0 · 2026-10-25

Protéger l'existant avant de consolider les skills : lignes 1 à 4 du rapport d'architecture du 25/10/2026.

- **Évals** : suite `claude plugin eval` dans `plugins/atelier-web/evals/`, 17 cas : orientation par `demarrer-projet-web` (3), déclenchement de huit skills clés (8), quasi-cas qui ne doivent rien déclencher (5), une landing de bout en bout assemblée depuis le modèle `evenement` (1). Les runs ne chargent ni `CLAUDE.md` ni `.claude/` : la doctrine de test d'une marque fictive (Brivalle) arrive en fixture, installée par le `scaffold_script` de chaque cas. Mode d'emploi, commande de référence et Δ : `evals/README.md`. Passage réduit de référence (un run par bras, Sonnet 5.5) : Δ moyen +0,07, ≈ +0,14 avec le cas de bout en bout lancé hors du dossier personnel, 3,82 $ ; lecture des cas à Δ nul et corrections à faire dans le même fichier.
- **Compaction** : `landing-page` (≈ 6 000 → ≈ 4 000 tokens) et `design-taste` (≈ 6 100 → ≈ 4 300) passent sous les 5 000 tokens que Claude Code réattache après compaction. Les invariants ouvrent chaque skill (ordre des phases, validations, contrôles bloquants, règles dures, reprise, chemins des références) ; le détail part dans `references/` (`assemblage.md`, `mesure.md`, `livraison.md`, `skills-orchestrees.md` pour l'une ; `stack-et-systemes.md`, `squelettes-motion.md` pour l'autre). Aucune règle retirée ; `design-taste` précise que le verrou de thème laisse passer les bandes sombres prévues par la charte d'une landing.
- **Hook** : `rappel-brand-check.py` voit aussi les pages écrites par script (`assemble-landing.py`, insertion scriptée d'un fragment). Matcher élargi à Bash : après une commande qui mentionne « atelier », il lint en un passage les pages et textes de `atelier/` modifiés depuis leur dernier contrôle, notés dans un registre de session du dossier temporaire. Toujours silencieux sans doctrine, ne bloque jamais.
- **Mouvement** : `motion-defilement` devient le cœur du motion, avec une pile par niveau (CSS piloté par le défilement d'abord, GSAP pour l'épinglage, Lenis en option, dotLottie pour les médias, Motion en React) et la règle des cinq secondes (WCAG 2.2.2). `animation-scroll-reveal` enseigne les apparitions en CSS natif, avec repli par `IntersectionObserver` et migration depuis AOS (sans version depuis 2018) ; `animation-lottie` enseigne dotLottie (`dotlottie-wc`, `dotlottie-web`, `dotlottie-react`) à la place de lottie-web (sans version depuis mai 2025). Recettes vérifiées dans Chromium, versions relevées sur npm. Les corps d'origine restent dans `references/` pour les projets existants. Descriptions en français, coût permanent ramené de ≈ 4 237 à ≈ 4 182 tokens.
- **Corrections** : les commentaires de `forms.js` portaient `{{PLACEHOLDER}}`, que `lint-brand.py` comptait comme trois erreurs sur toute page à formulaire (modèles `evenement`, `lead-magnet`, `demo-b2b` et `prestation` réassemblés) ; chemins `.claude/skills/landing-page/` hérités du cockpit remplacés par `${CLAUDE_PLUGIN_ROOT}/skills/landing-page/` dans deux agents, deux briefs et le README des sections ; renvoi de `design-redesign` vers les squelettes déplacés ; ligne d'installation dans le README du plugin.

## 1.0.0 · 2026-10-25

Première version.

- Plugin `atelier-web` : 24 skills, 7 agents, hook de lint de marque, fabrique (44 sections, 6 modèles de landing, 10 outils interactifs), modèles de doctrine.
- Extrait de la verticale web du marketing-cockpit-template (commit `eb01596`), découplé de l'arborescence du cockpit : la doctrine vit dans `atelier/marque/` du projet, les scripts lisent le projet courant (`ATELIER_PROJET`, `ATELIER_MARQUE`).
- Ajouts tirés de jessem.fr : `demarrer-projet-web`, `page-web`, `qa-rendu`, `motion-defilement`, `controle-fonds.py`, modèle `design.md`.
- Corrections au passage : conflit de nom dans `qa-landing.py`, marqueurs `{{MARKER}}` en commentaire qui faisaient échouer le lint des pages assemblées, en-têtes YAML de cinq skills et agents.
- `outils-complementaires/installer.sh` : installation de l'atelier et des plugins tiers depuis leur source.
- Référencement : README anglais et français, aperçu de partage, démos en ligne (`docs/`, GitHub Pages), README et licence dans le dossier du plugin avec la description de ce qu'il exécute et va chercher, métadonnées en anglais. Le catalogue des sections se génère dans le projet (`catalogue.json`) et n'est plus livré dans le plugin (limite de 256 Ko de l'annuaire officiel).
